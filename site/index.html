Self-hosted print gateway

One API between your business systems and every printer in the warehouse.

Your ERP or WMS sends a label, receipt or PDF with its own document id. Cloud Print Service turns it into the printer's language, delivers it once and only once, and tells you which printers are ready right now: Zebra label printers, receipt printers, office printers, on the network or on USB.

Deploy in 5 minutes View on GitHub
  • One Go binary + one JSON file
  • No database server (SQLite inside)
  • Operator panel built in
  • Never prints the same label twice

What it is for

Your business systems decide what to print. Cloud Print Service handles where and how, and whether it actually printed.

Shipping labels from the WMS

Send ZPL (or a PDF/PNG) to any Zebra-compatible label printer. Each job carries your order or parcel id. Resending it never makes a second label, even after a timeout or retry.

zebra9100 · ZPL

Receipts at the counter

Print ESC/POS receipts on 58 or 80 mm printers from Epson TM, Xprinter and others. Paper-out and cover-open are reported back to you.

escpos9100 · ESC/POS

Invoices and packing lists

Send a PDF, PNG or JPEG to an office laser or inkjet. CPS converts it for the printer: IPP, PCL/PostScript, or Epson ESC/P-R for EcoTank inkjets, in colour when the page has colour.

ipp · pdl9100 · escpr9100

USB printers on packing PCs

Plug a printer into a Windows or Linux PC, or into an ASUS router or AiMesh node, and run cps-agent there. The printer joins the fleet like a network printer. Its vendor driver can stay installed.

cps-agent · USB

See the whole fleet at a glance

One call returns every printer's state, paper and ribbon, queue depth and a plain usable yes/no. The live operator panel at /ui/ shows the same view, plus jobs, tokens and a ZPL preview.

GET /api/v1/printers/status

Integrate before the printers arrive

vprint is a virtual printer that speaks real ZPL, ESC/POS, IPP or PJL on a real socket. It renders every label to a PNG and can fake paper-out, offline or a crash mid-print.

vprint · test double

How it fits together

One server on the warehouse LAN. Network printers are reached directly. USB printers are reached through a small agent on the machine they are plugged into.

The life of a job

SubmitPOST /api/v1/jobs with your external_id. Sending the same id again returns the same job.
QueueJobs wait in a per-printer queue that survives restarts. A printer that is not usable holds its jobs and doesn't lose them.
SendCPS converts the document if needed and writes it to the printer once. Once the bytes have left, it never retries on its own.
Result printed the printer confirmed it sent_unknown sent, not confirmed: a person decides, so nothing prints twice failed it did not print; the reason is given

Quick start

For a Linux machine on the same LAN as the printers. You need Docker, or Go 1.26+ to build from source. About five minutes.

  1. Write a config

    Generate an admin key with openssl rand -hex 24 and list your network printers. Everything else has a working default.

    // config.json
{
  "addr": ":8080",
  "api_keys": {
    "PASTE-YOUR-ADMIN-KEY": { "client_id": "ops", "role": "admin" }
  },
  "printers": [
    { "printer_id": "wh1-pack-01", "name": "Packing station 1", "site": "wh1",
      "driver": "zebra9100", "host": "192.168.10.21", "port": 9100, "enabled": true }
  ],
  "discovery": { "enabled": true, "site": "wh1" }
}

  2. Start the server

    One container. The volume holds jobs, tokens and agent credentials. --network host lets discovery see the printers' mDNS; without discovery, -p 8080:8080 is enough.

    git clone https://github.com/kucial/cloud-print-service.git
cd cloud-print-service
docker build -f server/Dockerfile -t cps .
chmod 644 config.json
docker run -d --name cps --restart unless-stopped --network host \
  -v "$PWD/config.json:/etc/cps/config.json:ro" \
  -v cps-data:/var/lib/cps \
  cps
    Without Docker: build the binary 
    go build -o cps    ./server/cmd/cps
go build -o cpsctl ./server/cmd/cpsctl
sudo apt install poppler-utils fonts-liberation fonts-wqy-zenhei   # PDF conversion
./cps -config config.json

    For a systemd service and HTTPS behind Caddy or nginx, see the install guide.

  3. Check it

    Open http://<server>:8080/ui/ and log in with the admin key. Printers found by discovery wait under Discovery for you to adopt them. From a shell:

    curl http://<server>:8080/healthz                       # 200 OK
# the admin CLI ships in the image; the steps below use this alias
alias cpsctl='docker exec -e CPSCTL_URL=http://127.0.0.1:8080 -e CPSCTL_ADMIN_KEY=<admin-key> cps cpsctl'
cpsctl printers                                         # each printer, usable or why not

  4. Give your business system a token

    Each system gets its own token. It is shown once and stored hashed, and it can be rotated or revoked at any time.

    cpsctl token issue --client-id wms --ttl 365d

  5. Print

    Send ZPL as text, or any other format as base64. Use your own document id as external_id.

    curl -X POST http://<server>:8080/api/v1/jobs \
  -H "Authorization: Bearer $WMS_TOKEN" -H "Content-Type: application/json" \
  -d '{"printer_id":"wh1-pack-01","external_id":"SO-10042-label",
       "zpl":"^XA^FO50,50^A0N,50,50^FDHello CPS^FS^XZ"}'

# a PDF to an office printer: CPS converts it if the printer can't take PDF
curl -X POST http://<server>:8080/api/v1/jobs \
  -H "Authorization: Bearer $WMS_TOKEN" -H "Content-Type: application/json" \
  -d '{"printer_id":"hq-office-01","external_id":"INV-2026-0042","format":"pdf",
       "payload_base64":"'"$(base64 < invoice.pdf | tr -d '\n')"'"}'

curl -H "Authorization: Bearer $WMS_TOKEN" http://<server>:8080/api/v1/jobs/<job_id>

    The full API is browsable at http://<server>:8080/docs/ on your server.

  6. Add USB printers (optional)

    Make a one-time enrollment token on the server, then start the agent on the PC or router with that printer. The printer appears in the panel within about 30 seconds.

    cpsctl agent enroll --id pc7 --site wh1 --ttl 24h

    On the PC, take cps-agent from the release: on Windows, either cps-agent-gui.exe (enter the server address and token) or a service:

    :: Windows, Administrator command prompt
set CPS_AGENT_SERVER=http://<server>:8080
cps-agent.exe -enroll <token> -id pc7 -site wh1 -install

# Linux
CPS_AGENT_SERVER=http://<server>:8080 cps-agent -enroll <token> -id pc7 -site wh1 \
  -config /etc/cps-agent/agent.json

    On an ASUS router or AiMesh node, use the koolshare plugin or the /jffs package over SSH. The steps for each are in the install guide.

No printers yet? Run go run ./vprint/cmd/vprint -count 2 -id wh1-pack -render and start the server with server/config.example.json. The labels you print show up as images at http://localhost:19200.

Supported printers

The driver tells CPS how to talk to a printer. Every printer also takes PDF, PNG and JPEG: CPS converts them when the printer can't print them directly.

PrinterdriverStatus fromPrints directly
Zebra and ZPL label printerszebra9100printer status query, paper and ribbonZPL
ESC/POS receipt printers (Epson TM, Xprinter…)escpos9100real-time statusESC/POS
Office printers with IPP (most network lasers and inkjets)ippprinter state and the job's own recordwhat the printer reports (PDF, JPEG, URF…)
Office printers on JetDirectpdl9100PJLPCL, PostScript
Epson inkjets without IPP (EcoTank L-series)escpr9100reachability onlyESC/P-R, colour, A4
Any of the above on USBvia cps-agentas above, detected from the USB device idas above

Not supported: "host-based" printers that only work with their maker's PC driver, such as Canon CAPT lasers (LBP series) and some low-end GDI models. Look for IPP/AirPrint, PCL or PostScript in the spec sheet. Status of each printer family: STATUS.md.
